## Phase 2: Backend (Python/rotkehlchen) zum Laufen bringen

### 2.1 Python-Environment
- Python-Version prüfen: Briefing fordert 3.14+, `pyproject.toml` gibt den exacten Wert.
- `uv sync` im Root-Verzeichnis ausführen (Rotki nutzt `uv` für Dependency-Management — nicht `pip install`).
- Ggf. `uv sync --all-extras` falls optionale Features aktiviert werden müssen.

### 2.2 Smoke-Test Backend
Mögliche Verifikations-Kommandos (abhängig von dem, was `pyproject.toml` definiert):
- `uv run python -c "from rotkehlchen.accounting.cost_basis.base import CostBasisCalculator; print('OK')"` — Importtest des wichtigsten Moduls.
- `uv run pytest rotkehlchen/tests/unit/accounting/ -x --tb=short -q` — kleine Test-Subset laufen lassen, um sicherzustellen, dass die Environment korrekt ist.
- Bei fehlgeschlagenem Import: fehlende System-Libs (z.B. für SQLite/Rust-Bindings) identifizieren und dokumentieren.

**Windows-Hinweis:** Rust-Toolchain (`colibri/`, `crates/`) benötigt `cargo` — wird nur gebraucht, wenn die Rust-Komponenten gebaut werden. Für Python-Backend-Entwicklung ggf. nicht zwingend. Prüfen, ob `uv sync` das automatisch handhabt.

## Risiken & Mitigation

| Risiko | Mitigation |
|---|---|
| Windows-Build-Probleme mit Rust-Komponenten (`colibri/`) | Nur Python-Backend für DE-Entwicklung nötig. Rust überspringen, falls `uv sync` scheitert. |
| Python 3.14 nicht installiert | Vorab mit `python --version` prüfen; ggf. `uv python install 3.14`. |
| 515 MB Clone dauert lange / Netzwerk-Reset | Timeout hochsetzen; ggf. `--filter=blob:limit=10M` als Fallback. |
| Ticket-Beschreibungen leer (kein Detail in Plane) | Verifikation gegen das Briefing (Abschnitt 3), nicht gegen Plane-Text. |
| Frontend-Build schlägt fehl (Node-Version, etc.) | Backend-Priorität; Frontend-Setup wird dokumentiert aber nicht blockierend. |
